---
title: "The Shift Left Model in Secure Development"
description: "Moving security to the earliest stages of the cycle"
---

Shift left describes the principle of moving security activities to the earliest possible stages of the development cycle, instead of concentrating them at the end, right before deployment, where security audits were traditionally carried out as the last step before going to production. The reason for this change is fundamentally economic: fixing a vulnerability detected during design or while writing code costs a fraction of what it costs to fix the same vulnerability once the application is already in production and has potentially been exploited, considering development time, regression testing and the reputational risk involved. In practice, shift left means incorporating threat modeling while designing new features, running static code analysis on every commit, and giving developers security feedback directly in their usual work environment, instead of waiting for an audit report weeks later. A nuance that's sometimes misunderstood is that shift left doesn't eliminate the need for security testing in later stages, such as dynamic testing or manual penetration testing, but reduces the number of problems that reach those final stages, making that testing more efficient by focusing on risks that do require the real execution context.
