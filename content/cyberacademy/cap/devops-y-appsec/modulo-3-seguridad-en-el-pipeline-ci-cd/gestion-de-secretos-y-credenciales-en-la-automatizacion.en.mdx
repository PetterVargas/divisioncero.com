---
title: "Managing Secrets and Credentials in Automation"
description: "Preventing credentials from being exposed in pipelines"
---

CI/CD pipelines constantly handle sensitive credentials (API keys, deployment tokens, database passwords), and each of them is a high-value target because compromising the pipeline usually gives direct access to production, not just an isolated test environment. The most common and costly mistake is embedding secrets directly in source code or in versioned configuration files, where they remain visible indefinitely in the git history even if they're removed in a later commit, since anyone with access to the repository can recover them by reviewing earlier versions. The right practice is to store all secrets in a dedicated manager, inject them into the pipeline only at execution time through environment variables or direct integration with the manager, and apply the principle of least privilege here too, giving each pipeline stage only the credentials it actually needs for its specific task. Beyond initial management, it's essential to rotate secrets regularly and have automatic secret scanning on every commit, to immediately detect and revoke any credential accidentally leaked into the code before an attacker finds it.
