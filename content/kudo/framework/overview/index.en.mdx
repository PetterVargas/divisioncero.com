Create your Kudo app in seconds with our interactive CLI:

```bash tab="pnpm"

```

```bash tab="npm"

```

```bash tab="yarn"
yarn create @divisioncero/kudo-app
```

### Next steps after installing:

```bash tab="pnpm"
cd your-project
pnpm install
pnpm dev
```

```bash tab="npm"
cd your-project
npm install
npm run dev
```


## 🏛️ Document Governance

### Enterprise Context

This means the documents aren't only applicable to a specific project or team, but are intended to be used across the whole organization.

All documents are created and maintained in a hypothetical enterprise context named `DivisionCero`.

### Hypothetical Enterprise Context

- [X] A technology company that offers software as a service (SaaS).
- [X] It has software development, infrastructure, quality and security teams; also applicable in outsourced contexts.
- [X] It runs its infrastructure across multiple Cloud Service Providers (CSPs).
- [X] It maintains a 24/7 SOC (Security Operations Center) for continuous threat monitoring.
- [X] It has a team specialized in infrastructure security for implementing and maintaining controls.
- [X] It serves customers in several countries.
- [X] It employs people who work remotely.

### Roles and Responsibilities

- [X] **CEO (Chief Executive Officer):** Ultimately responsible for the organization's security posture and risk management strategy.
- [X] **CTO (Chief Technology Officer) & Technology Teams:** Ensure the secure implementation of systems and infrastructure following the defined policies.
- [X] **COO (Chief Operations Officer):** Oversees daily operations, ensuring security procedures are built into business processes.
- [X] **CFO (Chief Financial Officer):** Secures appropriate financial resources for security initiatives and evaluates security investments.
- [X] **CISO (Chief Information Security Officer):** Main sponsor of the information security policy framework and governance structure.
- [X] **SOC (Security Operations Center) Team:** Monitors threats in real time, detects security incidents, coordinates the initial response and keeps continuous watch over the technology environment.
- [X] **Infrastructure Security Team:** Implements and maintains technical security controls, manages secure configurations, performs vulnerability assessments and ensures system hardening.
- [X] **GRC (Governance, Risk & Compliance) Team:** Curators of the document architecture and responsible for the policy lifecycle.
- [X] **Legal & Privacy Office:** Ensures alignment with regulatory requirements and data protection obligations, provides legal guidance on security policies and handles security-related legal matters.
- [X] **Software Development:** Implements secure development practices and addresses security requirements in software products.
- [X] **Operations:** Maintains secure infrastructure configurations and operational security controls.
- [X] **Procurement:** Evaluates vendors' security practices and includes security requirements in contracts.
- [X] **Human Resources:** Manages security training, background checks and security aspects of personnel processes.
- [X] **Finance:** Manages the financial aspects of the security program and related expenses.
- [X] **Internal Audit:** Performs independent assessments of security controls and provides assurance of their effectiveness.
- [X] **All teams:** Responsible for understanding and complying with the established policies and procedures.

<Accordions type="single">
  <Accordion title="Versioning">
    Document versioning follows this naming scheme:

    - Continuous changes vX.Y.Z
        - X: Major version (significant changes)
        - Y: Minor version (improvements or minor changes)
        - Z: Patch version (bug fixes)
        - Example: v1.0.0 (initial version), v1.1.0 (improvements), v1.1.1 (bug fixes)

    - Releases grouped on the site as a whole are referenced by year and quarter:
        - Example: 2025-Q2 (initial version for the second quarter of 2025)
  </Accordion>
  <Accordion title="Change Control">
    Change control is carried out continuously with traceability through the git workflow; specifically through Pull Requests (PRs), which can be reviewed in the following [repository](https://github.com/PetterVargas/divisioncero.com). There's a direct link at the top right of the website.
  </Accordion>
  <Accordion title="Scope">
    We aim for this project's scope to be broad and its applicability in each context to be general, with an overall focus on technology contexts.
  </Accordion>
